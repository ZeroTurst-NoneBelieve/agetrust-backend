# PR #43 재리뷰 제출 초안

PR 본문과 재리뷰 설명에 사용할 참고 초안이다. 실제 제출 내용과 최신 CI/리뷰 상태는
GitHub PR #43에서 확인한다. 팀의 인증 계약 승인이나 키오스크 연동 완료를 뜻하지 않는다.

## PR 본문

### 작업 내용

- VC에 `credentialStatus`와 StatusList2021 context를 포함한다.
- 무작위 인덱스를 `secrets`로 배정하고 기존 사용 여부를 확인한다. 32회 충돌해도
  실제 빈자리 집합에서 선택하므로 빈자리가 있는데 확률적으로 실패하지 않는다.
- 정식 조회 경로는 `GET /api/v1/status-lists/{id}`다. 기존 VC 호환을 위해
  `/api/v1/status/{id}`도 유지하며 기존 DB URL과 서명된 VC를 바꾸지 않는다.
- 두 경로 모두 `Authorization: Bearer <api_key>`를 확인해 등록된
  ACTIVE 키오스크만 조회하게 한다. 304 처리도 인증 후에 실행한다.
- 인증 오류는 401/no-store이며 200/304는 `private, no-cache`와 `Vary: Authorization`을
  사용한다. 공유 캐시에서 인증 없이 목록을 재사용하지 않도록 한다.
- Holder 키 재바인딩 시 기존 VC 폐기와 목록 비트 변경을 같은 트랜잭션에 반영한다.
- VC 발급과 Holder 키 재바인딩은 같은 기기 행 잠금을 사용해 경쟁을 방지한다.
- 목록 변경 시 version과 updated_at을 갱신한다.
- 잘못된 base64url, gzip 오류, 16KB 미만 목록은 서명하거나 304로 응답하지 않고
  `503` + `Cache-Control: no-store`로 거부한다.
- `If-None-Match`가 일치하면 본문 없는 304, 목록이 바뀌면 새 ETag와 JWT를 반환한다.

### 검증

2026-09-08 현재 로컬 수정본에서 실행했다. Windows의 Python 3.12 가상환경과
격리된 PostgreSQL 15를 사용했다. CI의 Python 3.11 결과나 실제 키오스크 앱
실행 결과를 뜻하지 않는다. 백엔드 HTTP 검증은 ASGI 인프로세스 요청이다.

| 항목 | 결과 |
|---|---|
| ruff | 통과 |
| 전체 테스트 (DB 포함) | 145개 통과, 스킵 0개 |
| PostgreSQL 15 `alembic upgrade head` | 성공 |
| `alembic check` | 새 스키마 변경 없음 |
| 실제 키오스크 앱 연동 | 미구현·미검증 |

전체 145개는 단위 테스트 138개, 백엔드 E2E 3개, PostgreSQL 회귀 4개다.
발급 → 목록 비트 0 → 재바인딩 → 비트 1·새 ETag → 304와 기존 URL 호환,
동시 배정·강제 충돌·재시도 소진·updated_at 변경을 확인했다.
인증 테스트 16개와 실제 DB E2E에서 정식/호환 경로의 Bearer 키 검증,
비활성·폐기 키오스크 거절, 조건부 요청 우회 방지 및 캐시 헤더를 확인했다.
이전 X 헤더/사용자 JWT 거절, 키 해시로 정확한 키오스크 조회, 중복 키 해시 거절도 포함한다.

### 확인이 필요한 사항

- 상태 목록 조회를 #42의 예정된 `Authorization: Bearer <api_key>` 계약에 맞췄다.
  기존 `X-Kiosk-Key` 방식은 지원하지 않으며, 키 원문만으로 서버가 키오스크를 식별한다.
  동일 키 해시가 여러 키오스크에 저장돼 있으면 401로 거부한다.
- #42 결과 기록 API나 키 관리 API를 구현한 것은 아니다. #42에서는 인증된 키오스크와
  본문의 `kiosk_identifier` 일치 검증이 필요하다. 키 발급/회전 관리는 별도 작업이며,
  실제 키 전달·설치 절차와 일정은 관련 담당자와 조율한다. 개발 DB에 키를 생성하지 않았다.
- 키오스크 캐시·갱신·폐기 검사는 ADR-0013의 K-6 확장에 따라
  [mobile #12](https://github.com/ZeroTurst-NoneBelieve/agetrust-mobile/issues/12)와
  연결한다. 해당 구현은 아직 준비 전이며 백엔드만으로 실제 기기의 차단을 보장하지 않는다.
- 현재 원격 ADR의 제안·1시간 표기와 리뷰의 승인·5분 설명이 달라 최신 계약 확인이
  필요하다. 인증 도입으로 HTTP 캐시는 매번 서버 재검증을 요구하지만 자동 갱신
  스케줄이나 오프라인의 최신 폐기 반영까지 구현하는 것은 아니다.
- #44 머지 후 StatusList 오류도 공통 오류 형식에 맞추고 테스트한다. 아직 머지되지
  않은 타 PR 브랜치를 이 작업 브랜치에 병합하지 않았다.

### 제한

- 목록 131,072자리 소진 시 503이며 자동 분할은 후속 작업이다.
- 배정 잠금은 사용 여부 확인부터 INSERT·commit까지 유지한다. 이 잠금만 제거하면
  같은 빈자리를 두 요청이 배정할 수 있으므로 처리량 최적화는 후속 설계로 남긴다.
- PUBLIC_BASE_URL 공백 검증과 기존 DB URL 이관은 포함하지 않았다.
- 목록 JWT에 exp를 추가하지 않았다. 오프라인에서 오래된 목록을 허용하면 폐기
  반영이 늦어질 수 있으며 실제 동작은 키오스크 정책·연동 구현에 달려 있다.
- 배포 전 기존 공개 HTTP 캐시를 제거하거나 만료를 확인해야 한다. 키 폐기로 이후
  조회는 막을 수 있지만 이미 다운로드한 목록을 회수할 수는 없다.

Related to [backend #27](https://github.com/ZeroTurst-NoneBelieve/agetrust-backend/issues/27).
키오스크 작업의 범위 분리가 합의되기 전에는 자동 종료 키워드를 사용하지 않는다.

## 리뷰 답변 초안

1·7번은 secrets와 사용 여부 조회, 재시도 후 실제 빈자리 선택으로 반영했습니다.
2번은 정식 경로를 status-lists로 바꾸고 기존 VC용 경로는 호환 유지했습니다.
4·5·6번은 갱신 시각, 손상 목록 검증, 조건부 요청 304 처리와 테스트로 반영했습니다.

8번 잠금은 현재 배정 구조에서 INSERT·commit까지 유지해야 중복 배정 경쟁을
막을 수 있어 유지했습니다. 범위를 줄이는 최적화는 별도 예약/재시도 설계가 필요합니다.

3번은 기존 키오스크 API Key 인증을 정식/호환 경로 모두에 연결했습니다.
유효한 키를 가진 ACTIVE 키오스크만 200/304를 받을 수 있으며 캐시 정책도 수정했습니다.
#42의 예정된 Bearer API Key 계약에 맞춰 조회 인증도 변경했습니다. 이전 X-Kiosk-Key는
지원하지 않습니다. 키 관리 기능은 별도 범위이며, 키오스크 실제 연동은 K-6(#12)
담당자와 일정을 맞춰 후속으로 진행하겠습니다.

## 팀장님께 전달할 배경 설명

현재 #27은 기존 VC가 폐기됐는지를 목록으로 제공하는 작업입니다. 키오스크는 사용자가
보여 준 VC의 번호를 이 목록에서 찾아 폐기 여부를 확인하게 됩니다.

목록에 이름이나 생년월일이 담기는 것은 아닙니다. 다만 특정 VC의 번호와 목록 주소를
알면 그 VC가 폐기됐는지는 확인할 수 있습니다. 그래서 우리 서비스에서 사용하는 등록된
키오스크만 조회하도록, 기존 API Key 인증을 새 경로와 이전 경로에 모두 연결했습니다.
키가 틀리거나 사용 중지된 키오스크는 목록을 받을 수 없습니다.

요청 형식은 #42 계약에 맞춰 `Authorization: Bearer <api_key>`로 통일하기로 했습니다.
Bearer 뒤에는 사용자 로그인 토큰이 아니라 키오스크 API Key 원문만 보내면 됩니다.
키 발급/회전 관리 기능은 별도 작업으로 남기고 실제 전달·설치 절차는 담당자와 조율하겠습니다.
키오스크에서 목록을 갱신하고 폐기된 VC를 거절하는 기능은 담당자와 일정을 맞춰 후속으로
진행할 예정입니다. 이번 헤더 통일만으로 오래된 목록 문제가 해결되는 것은 아닙니다.
